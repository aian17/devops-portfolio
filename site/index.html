AI-first

How I work

AI-first, to me, is a discipline of delegation: machines own execution, while I retain judgment, accountability and taste. Every agent I build operates within explicit guardrails, and every output is verified before it reaches production.

01

I pair with AI every day

Claude helps me draft Terraform and scripts, explain errors and think through designs. I read, test and own every line that ships.

02

AI inside the pipeline

Every infrastructure pull request on this site is reviewed by an AI agent that explains the Terraform plan in plain language.

03

Guardrails before cleverness

The agent can only comment. It has a read-only role, deterministic risk checks, masked account IDs, and it treats the plan as untrusted input.

04

Next stop: AIOps and MLOps

I'm growing from cloud and DevOps toward automating operations with AI, and toward the infrastructure that machine learning runs on.

Infrastructure

A private S3 bucket, served over CloudFront, deployed by GitHub Actions

Every part of this — the bucket, the distribution, the DNS record, the certificate — is defined in Terraform with remote state in S3. GitHub Actions runs plan on every pull request and apply on merge, authenticating to AWS via OIDC rather than long-lived credentials.

Pull request guardrail

An AI agent reviews every infrastructure change

On each pull request that touches terraform/, a read-only role runs terraform plan and the workflow posts one comment: a change table, deterministic risk flags (destroys, IAM, anything open to 0.0.0.0/0) and an AI summary. The agent can only comment, never apply.
